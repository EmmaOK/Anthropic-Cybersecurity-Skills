## `phantom_mcp_server.py`

- **Hard dependency: the `mcp` Python SDK.** Imports `mcp.server`; on a fresh checkout the
  import succeeds as a namespace package but `mcp.server.Server` is missing, so the server fails
  silently. Install `mcp` into whichever Python `../.mcp.json`'s `python3` resolves to — see
  `../.claude/mcp-servers.md` for the exact commands.
- **Rich index (`_build_rich_index`)** — at startup the server parses every `skills/*/SKILL.md`
  frontmatter (`_parse_frontmatter`) to populate `subdomain` + `tags` + `has_script`, using
  `index.json` only as a description fallback. This is what makes `search_skills` /
  `list_subdomains` report real subdomains instead of `unknown`. The index is memoized in
  `_RICH_INDEX`. If you add fields to `SKILL.md` frontmatter that tools should expose, surface
  them here.
- The server returns `TextContent`; tool schemas are defined in the `list_tools` handler and
  dispatched in the `call_tool` handler.

### `index.json` and the rich index
`index.json` carries `name`, `description`, `domain`, `subdomain`, `tags`, `path` per skill
(generated by `../.github/workflows/update-index.yml` — ADR-0005, never hand-edit). The server's
rich index re-parses frontmatter for freshness and `has_script`; `index.json` is the fast
catalog used by `../phantom/skill_loader.py`. Keep the two in sync by regenerating the index
(don't hand-edit either side).

## Conventions when editing here
- No hard-coded credentials — read from env (`../.claude/conventions.md`). `.mcp.json` defaults
  are placeholders; real secrets come from the launching shell.
- Backend-dependent servers must **fail closed** when their backend is unreachable (ADR-0007),
  so the whole set stays safe to leave registered.
